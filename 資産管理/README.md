# 資産管理

GMOコイン・SBI証券(国内株式/投資信託/米国株式)・ドコモSBIネット銀行・PayPay・りそな銀行（資産）と、
三井住友カード・セゾンゴールドカード・JCBカード（負債）の純資産を週次で追跡し、
あわせてクレジットカードの支出をカテゴリ別に可視化するツール。

## セットアップ

1. `pip install -r requirements.txt`(openpyxlを含む)
2. `config.env` を確認（既に Gmail 通知用の資格情報は `gmo_dca/config.env` から複製済み）
   - `GMO_API_KEY` / `GMO_API_SECRET` は空欄のまま。GMOコインの**残高照会専用の新規APIキー**を
     発行して設定することを推奨（発注権限つきの既存キーをそのまま流用しない）
   - `OBSIDIAN_VAULT_PATH` は既定でVaultパスが入っている。Vaultへの書き戻しが不要なら空にする
   - `ASSET_SYNC_DIR` は個人用OneDrive内のフォルダ（既定で設定済み）。ここに`残高入力.xlsx`と
     `dashboard_latest.html`が置かれ、OneDriveが自動でクラウド同期する。未設定ならローカルのみで運用

## 使い方

```bash
python main.py remind    # 週次リマインド: GMO自動取得 + 入力用Excel更新 + Gmail通知
python main.py commit    # 週次コミット: カード請求額自動反映 + CSV取込 → 台帳確定 → ダッシュボード生成 → Vault書き戻し → 通知
python main.py report    # 台帳の現状からダッシュボードのみ再生成（通知なし）
```

`remind` と `commit` は Gmail 通知を送信する（`config.env` に `GMAIL_ADDRESS` 等が設定されている場合）。
実行すると実際にメールが届くので、テストだけしたい場合は `notifier.NOTIFY_ENABLED` を一時的に `False` にするか、
`report` コマンドで代用すること。

### 週次の運用フロー

1. `remind` が `残高入力.xlsx`（**常に同じファイル**、日付は変わらない。`ASSET_SYNC_DIR`配下=個人用OneDrive内）
   を更新。GMOコインの残高は自動入力済み。カードCSVが既に`expenses/incoming/`にあれば請求額も自動反映される
2. `残高入力.xlsx` をExcel等で直接開き、「今回残高」列（黄色ハイライト）を埋める。
   - GMOコイン以外の口座（SBI証券×3・ドコモSBIネット銀行・PayPay・りそな銀行）は手入力
   - 三井住友・セゾン・JCBは、対応するカード明細CSVを`expenses/incoming/{smbc|saison|jcb}/`に置いておけば
     `commit`実行時に請求額が自動で埋まる（置かなければ従来通り手入力）
   - 負債（クレカ）は請求額を**正の数**で入力する
3. `commit` を実行すると、未入力口座が残っている場合は確定されず警告通知が届く。
   全て入力済みなら確定・ダッシュボード生成・Vault書き戻しが行われ、確定内容は
   `archive/残高入力_YYYYMMDD.xlsx` として保存されたうえで
   `残高入力.xlsx` の「今回残高」列は次回入力用に空にリセットされる

### スマホからの利用（OneDrive経由）

`ASSET_SYNC_DIR`（個人用OneDrive内の`資産管理`フォルダ）に以下が同期される。PCのOneDriveクライアントが
自動でクラウドへアップロードするので、追加の手動アップロード操作は不要。

- `残高入力.xlsx` — スマホのOneDriveアプリ or Excelアプリで開いて「今回残高」列を直接編集できる
- `dashboard_latest.html` — `commit`/`report`のたびに最新版で上書きされる。スマホのOneDriveアプリで
  開き、プレビューでグラフが表示されない場合は「ブラウザで開く」を選ぶとChart.jsのグラフが正しく表示される

編集内容はOneDrive経由でPC側にも同期されるため、次に`commit`を実行すればスマホから入力した値がそのまま反映される。

### 専用アプリ「マネーパルス ライト」（Claude Artifact）

OneDrive+Excelとは別に、スマホでアプリのように使える専用ページを用意した。
公開先: https://claude.ai/code/artifact/ab5b5f4b-e2e4-495a-a9d3-2756f392c1ec

（デザイン検討時に「資産手帳」「マネーパルス（ダーク）」「マネーパルス フュージョン」「通帳ノート」も
試作したが、最終的に「マネーパルス ライト」に決定。他の試作版はArtifactギャラリーから手動削除可能）

- **ダッシュボードタブ**: 純資産推移・資産負債内訳・支出カテゴリをアプリ内データベースから表示
- **入力タブ**: GMOコイン以外の口座の「今回残高」をその場で入力・保存（保存はアプリ内で完結、Claude不要）
- 保存しただけではまだ確定しない。入力が終わったら **Claudeに「確定して」と伝える**と、以下が行われる:
  1. GMOコインの最新残高をAPIから取得
  2. アプリの入力値を `sync_from_app.py` 経由で `残高入力.xlsx` に反映
  3. 既存の `commit` パイプラインで確定・記録・ダッシュボード生成・Vault書き戻し
  4. 最新の結果をアプリのデータベースにも反映し、入力欄をクリア

アプリのデータ（入力値・履歴）はAnthropicのクラウド基盤（このArtifactのデータベース）に保存される。
OneDrive/ローカルファイルのみで完結させたい場合はExcel版（上記）をそのまま使えばよい。

## 支出カテゴリ分類のチューニング

`expenses/category_rules.json` にキーワードを追記すると、次回の取込から自動分類の精度が上がる。
「未分類」の取引はダッシュボード上で赤字強調される。全角/半角は自動で正規化されるため、
キーワードはどちらの表記で登録しても一致する。短すぎるキーワード（例: "au"）は無関係な単語に
誤って一致することがあるので、できるだけ具体的な文字列を使うこと。

## カードCSVパーサーについて

三井住友カード(Vpass)・セゾンゴールドカード・JCBカード(MyJCB)の実データで確認済みのフォーマットに対応。
いずれも単純な「ヘッダー+明細」ではなく、請求額等のサマリー行が前に付く形式だったため、
ヘッダー行を冒頭数行から自動探索する方式（三井住友のみヘッダー無しの固定列順）にしている。
各パーサーは請求額合計の自動抽出（`extract_billing_total`）にも対応している。
列が認識されない場合は `expenses/parsers/{smbc,saison,jcb}_parser.py` の `*_COL_CANDIDATES` を調整すること。
